# Jev 浏览器执行

ProfilePilot 默认使用 **Jev 优先执行**，借鉴 [browser-use/jev-ultrafast](https://github.com/browser-use/jev-ultrafast) 的动态动作选择、紧凑页面观察和按需文本辅助设计。浏览器连接和授权继续由 ProfilePilot Gateway 管理；未复制该项目的浏览器连接实现，也未修改或训练 Jev 模型。

## 配置

浏览器任务 → 设置 → Jev 浏览器执行。现有密钥保持有效，运行方式默认“Jev 优先执行”，可切回“主模型执行，Jev 辅助判断”。旧配置没有运行方式时采用新默认，显式保存的辅助模式不变。

TypeSafe 官方直连：`POST https://api.typesafe.ai/v1/systemone`，模型 `jev-latest`。Vercel 仍使用 AI SDK 7 Evaluation 和 `typesafe-ai/jev`。主模型、TypeSafe、Vercel 凭据分别由 Electron safeStorage 加密保存，不写入任务 JSON 或页面。Jev Key 不交给 SDK 工作进程；主模型 Key 通过本机私有 IPC 交给工作进程。服务切换不会将另一服务的 Key 发送到新地址。

## 执行流程

1. 从用户明确提供的 URL 开始，单次页面读取获取文字、控件、当前值和稳定元素引用。
2. 一个 Jev 请求同时提供操作选项和对应候选元素；只消费所选操作对应的目标答案。支持点击、文本填写、原生下拉框、滚动、等待、完成判断与人工接管。
3. 所有动作经过现有任务服务的页面检查、授权或确认、回执记录，再由 Gateway 执行。
4. 需要文字时，通过已配置的 Kimi / Anthropic 兼容 Messages 接口准备当前表单的已知内容，结构不变时复用。缺少资料则询问用户。
5. Jev 判断完成，或已有进展但下一步不确定时，重新观察并单独调用主模型核查结果。必须提供当前页面原文证据，不能用点击成功证明提交成功。
6. 复杂规划、附件、批量项目、恢复后的记录核查、不支持的控件或无法确认的结果，交由原 Claude Agent SDK 继续，保留历史和回执；不再给每次观察额外附加 Jev 调用。

Jev 接收目标、授权范围、近期用户补充、页面文字、控件和操作摘要。文本辅助模型还接收当前任务选定的资料。不额外向 Jev 发送附件全文，但页面和已填写的字段可能包含个人信息。

候选来自实际页面，不接受模型生成脚本、选择器或任意元素 ID。所选操作和目标必须具有完整概率分布且是最大概率项，概率和服务置信度均至少为 0.65；此阈值尚未经过广泛业务校准。缺失或非法答案不能执行动作。

每任务最多 100 次 Jev 判断、12 次文本辅助，单次超时分别为 6 秒和 45 秒，另有任务时间和动作次数上限。不会自动重试有外部影响的动作。暂停、取消和退出中止模型请求，配置变化后不能执行旧结果。

单次页面读取和动作通过 Gateway 受控接口复用原 Session，不能直连 Chrome 或越过接管。执行前检查文档、节点引用、值、链接地址和表单信息，并检查遮挡。Windows 点击前生成绘制帧；macOS 使用相同 Gateway 与 DOM 路径。提交确认、授权网站和次数限制、支付交还、重复操作限制与中断恢复仍生效。

Jev 与文本辅助分别记录调用数、token 和耗时，**不计入 SDK 估算金额及其费用上限**。SDK 用量为零不代表任务免费。实际金额查看对应服务商账单；文本辅助输入 token 包含服务返回的缓存读取和创建 token。

## 兼容辅助模式

保留原先每次 SDK observe 后的页面状态、下一步、人工要求、操作影响评估。维持 2.5 秒超时、相同上下文缓存、失败后本次运行停用、配置切换失效以及 100 次调用上限。官方 noul 转换为内部布尔概率，页面及下一步置信度均达到 0.8 才供主模型参考。此模式由主模型执行动作。

## 2026-09-20 验证

- 构建、67 项任务测试、桌面 E2E 均通过，包含运行方式切换和真实 preload / IPC。
- 真实 Windows Chrome / Gateway 验证 8 项保护：原生输入语义、值变化、链接目标变化、节点替换、遮挡、单次点击、换文档和密码值排除。记录：`test-results/browser-tasks/fast-guards-result.json`。
- 使用真实 Jev、Kimi API 和独立测试 Profile 完成相同本地表单：姓名、邮箱、城市、勾选、提交、核查回执。每次都由测试站后台独立确认恰好一条正确记录。

### 六类任务、三轮复测

随后复用 Garden Lab 的动态列表、分页商品、实时事件、重复检查、登录与 Shadow DOM、文件上传六张原任务卡，执行两种模式各三轮，共 36 次尝试。Jev 优先通过 17/18，原流程通过 18/18；Jev 组 15/18 次仍启动完整 SDK。实时事件的成功耗时中位数为 14.0 秒对 44.8 秒，其余任务收益不同，不能将上面的单表单样本推广为整体提速比例。

第 32 次分页任务未交付要求的对象数组，并在 partial 状态等待 SDK 收尾时触发超时回调异常。保留该条失败、核验代码哈希后只继续剩余四条，未重跑替换。评测结束后修复已终结任务的超时收尾，新增 completed / partial / failed 三项回归，任务相关测试 70/70 通过；本批原始成绩不变。此前页面控制条错误采用 Agent CDP Session 的问题也已修复，本批连接归属错误为零。

完整条件、每次记录、失败说明及改进方向见 [Garden Lab 36 次评测归档](https://github.com/ffffhx/garden-lab/tree/main/apps/browser-tool-bench/results/jev-core-2026-09-20T12-39-30-184Z)。这仍是 Windows 本地靶场的小样本产品模式比较，不是 Jev 单模型与通用 Agent 的独立对照。
