# 无线调试开关开启但无法连接

Android 的无线调试开关与 `adbd` 进程状态是两项独立证据。开关开启、电脑仍在配对列表中，不代表当前端口正在监听。

在 Android 13 真机上观察到过：无线调试开关保持开启，旧端口拒绝连接，mDNS 没有连接服务，系统 `AdbDebuggingManager` 持续记录 `Caught an exception opening the socket: java.io.IOException: No such file or directory`。关闭再开启无线调试后，端口改变、连接恢复。上述证据能定位调试服务失效，不能单独说明是谁停止了系统进程。

## 恢复条件

高级自动恢复新增了对此故障的检查：

- 已开启自动恢复和高级恢复，已有电脑配对及 `WRITE_SECURE_SETTINGS` 授权。
- Wi-Fi 仍连接，无线调试开关明确开启，没有有效电脑连接或活动控制会话。
- 在后台读取 `init.svc.adbd`，连续至少 20 秒确认其为 `stopped`。`running`、`restarting`、空值、读取拒绝或超时均取消本次故障判断。
- 使用已授权的系统设置接口短暂关闭再开启无线调试，与断网恢复共用每 30 分钟最多 3 次的持久化预算。
- 短暂关闭操作有最长 10 秒的事务记录。授权撤回、关闭自动恢复、网络变化或过期时不继续恢复。连接成功以实际 Wi-Fi 心跳确认，不以开关值代替。

不在网络稳定时重新开启用户关闭的调试开关，不启动或恢复控制会话，不重放输入。系统不允许读取状态或写入设置时仍需用户在无线调试页面手动处理。

## 验证

`npm run build:phone` 执行开发版构建、单元测试与 Android Lint。`RecoveryPolicyTest` 覆盖持续停止、未知状态、失去恢复资格、重试预算及事务过期。`AdbDaemonProbeTest` 需要真实在线设备，用于验证 App 进程能够读取系统调试服务状态；它不证明自动重启故障的完整闭环。

断开电脑连接后等待至少 30 秒，再连接先前仍在运行的端口，可验证正常的 `adbd` 不会因为电脑断连被误重启。重新连接后应保持原控制会话结束。

修复运行在 Android 端，不依赖 Windows/macOS 的主机命令。Windows 真机连接已经验证；macOS 主机组合仍需单独验证。
