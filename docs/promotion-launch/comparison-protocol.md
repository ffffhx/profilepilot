# 三方比较：执行协议与记录表

目标是判断任务适配程度，不预设赢家。当前没有完成 browser-use、agent-browser、ProfilePilot 的同条件比较，不发布速度、成功率或 token 优势数字。

## 固定条件

记录三款工具版本、对应官方入口、同一 Agent／模型版本、系统、Chrome 版本、网络、页面数据、登录前提、任务输入与截止条件。browser-use 使用面向外部 Agent 的 CLI 路径，不能拿它额外的 Python Agent 模型循环与另两者直接比较。每项任务预登记三次；保留失败及人工介入，不能仅选择最好一次。

## 分开比较的任务

| 任务 | 输入与限制 | 成功标准 |
| --- | --- | --- |
| 通用网页 | 同一公开仓库页面，查找 Windows 安装文件；不下载安装 | 名称、原链接与实际页面一致，说明证据日期，会话结束 |
| 专用站点 | 相同登录条件、相同闲鱼规格和预算，最多读取 10 条候选、5 条详情；不联系或购买 | 原链接可核对，单条／套装有证据，待确认与排除分开；记录筛选是否生效和部分结果 |
| 多目标协作 | 两个明确分离的 Profile，分别完成同一只读任务；再尝试进入已占用目标 | 独立任务均完成；占用被明确拒绝，原任务不受影响；结束后无残留控制会话 |

站点适配任务单独报告：现成适配减少的准备工作可以计入，但不能将该结果推广为所有网页任务都更快。不同工具支持范围不一时填「不适用／未配置」，不能直接当作任务失败。

## 记录与评分

记录业务结果、准备用时、执行总用时、人工介入次数、失败／阻塞原因、模型提供方实际返回的 token 用量及证据路径。模型未报告用量时填空，不估算为 0。用时至少区分首次安装与已连接运行。

现有基准集在 benchmarks/agent-tasks；其中 synthetic、live-site、recovery 分开计分。目前没有两款竞品的现成适配器，本协议和 comparison-runs.csv 是执行准备，不是已跑完的测评。

依据：https://docs.browser-use.com/open-source/browser-use-cli 、https://agent-browser.dev/sessions 、https://agent-browser.dev/cdp-mode 。执行前重新核对实际版本的官方帮助。
