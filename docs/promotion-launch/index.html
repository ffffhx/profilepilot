V2EX

标题：做了个给 Claude Code / Codex 用的工具，读取闲鱼、小红书，也能连接安卓

大家好，分享一个自己在做的 MIT 开源项目 ProfilePilot。

它给 Claude Code、Codex 等已有 Agent 提供一套本地 CLI：连接已登录的 Chrome、本地 Electron 应用和安卓手机。

browser-use、agent-browser 已经很好用了，也有复用登录态和多会话的办法。我做这个项目，主要想把自己反复用到的任务准备得更直接一些。

比如找闲鱼商品。告诉 Agent 规格、预算、排除条件，再让它搜索候选、核对详情，整理标题、挂牌价、原链接，以及还需要确认的信息。之后再次采样，可以比较自己的采样记录；它不能凭空补出过去一年的价格。

当前源码内置 9 个站点、21 项读取操作，包括闲鱼、小红书、B站、BOSS 等。各站能力不同：小红书评论只包括实际加载的部分，YouTube 字幕需要视频本身已有字幕。无结果、读取失败和只读到部分内容也要区分。

另一个重点是目标管理。不同 Agent 可以分别使用不同 Profile 或独立应用。一个查资料，一个检查本地项目；同一 Profile 被占用时会提示，不能直接抢走。需要我登录或处理页面时，可以接管，之后再交还。

浏览器、Electron 和安卓分别走 ppilot browser、ppilot electron、ppilot phone，配套提供 Skill。日常 Chrome 通过扩展连接；外部浏览器控制不需要桌面管理窗口一直打开，也不会额外启动一套模型循环。

这还是早期项目。桌面端有 Windows / macOS，扩展目前按引导手动加载，商店进度以项目说明为准。本地 Profile 和记录在电脑上，但交给 Agent 的页面内容、截图可能发送到你选用的模型服务。

如果你已经有顺手的工具，可以先试一次站点读取或网页加安卓的任务，看看这些现成流程是否有帮助。我尤其想了解：第一次安装卡在哪里，以及最后结果有没有真的完成你的任务。

常见回复

为什么不用 browser-use / agent-browser？

都可以，也不用为了 Star 数换工具。ProfilePilot 更想解决的是现成中文站点读取、本地目标管理和安卓协作。多会话、登录态、CLI 本身都不是独有功能；建议用你自己的任务试一次。

更快或更省 token 吗？

还没有三方同条件的数据，所以目前不做排名。比较协议已准备，会同时记录失败、人工介入和实际模型用量。

能在同一个 Profile 的多个标签页同时跑吗？

这里说的并行是不同 Profile / 独立应用。同一受控 Profile 保持一个控制会话；多个 Agent 不能同时操作同一部手机或共享桌面鼠标。

会上传账号吗？

Profile 与本地记录在本机。Agent 为完成任务读取的网页内容、截图和结果可能发送给你使用的模型服务。请查看扩展隐私说明并按任务范围授权，不能把“本地工具”理解为“所有数据永不离机”。

不配置模型能用吗？

使用已有外部 Agent 时，控制命令本身不再启动模型循环。内置 Agent 是另外一条可选路径，首次上手不要求使用它。

商店里能装了吗？

目前未确认 Chrome Web Store 上线状态，先按当前安装说明手动加载。只有后台实际发布后，才替换成真实商店链接。

  7. 运行 ppilot browser --session store-review complete，核对控制权释放。使用自己创建的测试历史与下载文件补验 history / downloads；不要读取私人历史或下载资料。

第一轮试用执行包

招募对象：已使用 Claude Code／Codex、有真实网页任务的开发者。首轮邀请 5–10 人，Windows、macOS Apple Silicon 与 Intel 尽量都有。以下邀请稿未发送。

邀请稿

我在做 ProfilePilot，让现有 Agent 读取已登录的 Chrome、部分中文网站，并连接 Electron 和安卓。想请你从安装开始，试一个你确实需要的只读任务。大约预留 15–20 分钟；不要求成功，也不用给好评。最有帮助的是告诉我：哪一步看不懂、是否需要人帮忙、最终结果是否能核对。可以只分享脱敏步骤，不需要提供账号或原始日志。你愿意的话，我发安装说明和反馈入口。

每位试用者的流程

  1. 记录系统、芯片、Chrome、App、CLI、扩展和 Agent 版本，以及是否已有登录态。
  2. 从公开下载链接开始计时，独立完成安装、扩展配对、CLI／Skill 安装。记录每个卡点及人工帮助次数。
  3. 由试用者选择一个只读任务。提前写出成功标准，不能由工具的 ok 回包代替核对。
  4. 检查结果与原链接、连接目标、会话是否结束；记录成功／部分／失败／阻塞。
  5. 七天后，经试用者同意再询问是否再次使用、用了什么任务、有没有新的卡点。

不要为降低用时替试用者预先配好环境。5 分钟只是设计目标，不作为已验证宣传成绩。

Windows 和 macOS 分开记录

两边都检查中文／空格路径、PATH、持久扩展目录、Chrome 重启、升级后配对保留。Windows 额外检查 PowerShell 中文和参数、Android USB 驱动；macOS 记录芯片、安装与签名提示、真实设备连接。没有 macOS 真机记录就填「未验证」。不把模拟器或 Windows mock 当成真机通过。

四项观察指标

  • 连接完成率 = 实际完成连接的人数 / 已开始安装的人数。
  • 首次任务成功率 = 按预定标准核对通过的人数 / 已尝试首次任务的人数。部分完成和阻塞单列。
  • 七日复用率 = 确认七日内再次使用的人数 / 已满七日且有回访结果的人数；另报失访人数。
  • 重复卡点 = 相同问题影响的人数与出现的步骤；优先修复影响首次成功的问题。

小样本报告同时写分子、分母，不只报百分比。无遥测时使用自愿反馈，不用 Star 或下载次数推测实际留存。

发布顺序

下载版验证完成后，先在一个开发者社区发布并集中答疑；收集一轮卡点、修复后再发 X；最后选择一个已核对的真实任务发小红书图文。视频由项目作者自行安排，不再作为本包的交付内容。渠道之间留出处理反馈的时间，不承诺流量或所谓最佳时段。

三方比较：执行协议与记录表

目标是判断任务适配程度，不预设赢家。当前没有完成 browser-use、agent-browser、ProfilePilot 的同条件比较，不发布速度、成功率或 token 优势数字。

固定条件

记录三款工具版本、对应官方入口、同一 Agent／模型版本、系统、Chrome 版本、网络、页面数据、登录前提、任务输入与截止条件。browser-use 使用面向外部 Agent 的 CLI 路径，不能拿它额外的 Python Agent 模型循环与另两者直接比较。每项任务预登记三次；保留失败及人工介入，不能仅选择最好一次。

分开比较的任务

任务 输入与限制 成功标准
通用网页 同一公开仓库页面，查找 Windows 安装文件；不下载安装 名称、原链接与实际页面一致，说明证据日期，会话结束
专用站点 相同登录条件、相同闲鱼规格和预算，最多读取 10 条候选、5 条详情；不联系或购买 原链接可核对，单条／套装有证据，待确认与排除分开；记录筛选是否生效和部分结果
多目标协作 两个明确分离的 Profile，分别完成同一只读任务；再尝试进入已占用目标 独立任务均完成；占用被明确拒绝，原任务不受影响；结束后无残留控制会话

站点适配任务单独报告：现成适配减少的准备工作可以计入，但不能将该结果推广为所有网页任务都更快。不同工具支持范围不一时填「不适用／未配置」，不能直接当作任务失败。

记录与评分

记录业务结果、准备用时、执行总用时、人工介入次数、失败／阻塞原因、模型提供方实际返回的 token 用量及证据路径。模型未报告用量时填空，不估算为 0。用时至少区分首次安装与已连接运行。

现有基准集在 benchmarks/agent-tasks；其中 synthetic、live-site、recovery 分开计分。目前没有两款竞品的现成适配器，本协议和 comparison-runs.csv 是执行准备，不是已跑完的测评。
