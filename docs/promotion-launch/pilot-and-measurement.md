# 第一轮试用执行包

招募对象：已使用 Claude Code／Codex、有真实网页任务的开发者。首轮邀请 5–10 人，Windows、macOS Apple Silicon 与 Intel 尽量都有。以下邀请稿未发送。

## 邀请稿

我在做 ProfilePilot，让现有 Agent 读取已登录的 Chrome、部分中文网站，并连接 Electron 和安卓。想请你从安装开始，试一个你确实需要的只读任务。大约预留 15–20 分钟；不要求成功，也不用给好评。最有帮助的是告诉我：哪一步看不懂、是否需要人帮忙、最终结果是否能核对。可以只分享脱敏步骤，不需要提供账号或原始日志。你愿意的话，我发安装说明和反馈入口。

## 每位试用者的流程

1. 记录系统、芯片、Chrome、App、CLI、扩展和 Agent 版本，以及是否已有登录态。
2. 从公开下载链接开始计时，独立完成安装、扩展配对、CLI／Skill 安装。记录每个卡点及人工帮助次数。
3. 由试用者选择一个只读任务。提前写出成功标准，不能由工具的 ok 回包代替核对。
4. 检查结果与原链接、连接目标、会话是否结束；记录成功／部分／失败／阻塞。
5. 七天后，经试用者同意再询问是否再次使用、用了什么任务、有没有新的卡点。

不要为降低用时替试用者预先配好环境。5 分钟只是设计目标，不作为已验证宣传成绩。

## Windows 和 macOS 分开记录

两边都检查中文／空格路径、PATH、持久扩展目录、Chrome 重启、升级后配对保留。Windows 额外检查 PowerShell 中文和参数、Android USB 驱动；macOS 记录芯片、安装与签名提示、真实设备连接。没有 macOS 真机记录就填「未验证」。不把模拟器或 Windows mock 当成真机通过。

## 四项观察指标

- 连接完成率 = 实际完成连接的人数 / 已开始安装的人数。
- 首次任务成功率 = 按预定标准核对通过的人数 / 已尝试首次任务的人数。部分完成和阻塞单列。
- 七日复用率 = 确认七日内再次使用的人数 / 已满七日且有回访结果的人数；另报失访人数。
- 重复卡点 = 相同问题影响的人数与出现的步骤；优先修复影响首次成功的问题。

小样本报告同时写分子、分母，不只报百分比。无遥测时使用自愿反馈，不用 Star 或下载次数推测实际留存。

## 发布顺序

下载版验证完成后，先在一个开发者社区发布并集中答疑；收集一轮卡点、修复后再发 X；最后选择一个已核对的真实任务发小红书图文。视频由项目作者自行安排，不再作为本包的交付内容。渠道之间留出处理反馈的时间，不承诺流量或所谓最佳时段。

空白记录表见 pilot.csv、feedback.csv、release-queue.csv。没有填入虚构用户和指标。
